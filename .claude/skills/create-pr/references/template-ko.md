# 한국어 PR 템플릿

한국 프로젝트(한국어로 소통하는 팀·저장소)에서 사용한다. 모든 섹션은 실제 diff와 커밋을 근거로 채운다.
해당 없는 섹션은 "없음"이라고 쓰지 말고 제목째 지운다.
아래에서 `>`로 시작하는 줄은 작성 안내다. PR 본문에 옮기지 않는다.

---

## 요약

> 1~3문장. 무엇을, 왜 바꿨는지. 사용자에게 보이는 효과나 해결한 문제를 먼저 쓴다.

## 변경 유형

> 해당하는 것에만 x 표시. 커밋 메시지 type과 같은 기준이다.

- [ ] feat: 사용자에게 보이는 새 기능·동작
- [ ] fix: 버그 수정
- [ ] refactor: 동작 변화 없는 구조 개선
- [ ] chore: 설정, 의존성, 문서, 도구 등

## 변경 내용

> 파일이 아니라 동작 기준으로 묶은 항목. 항목당 한 줄. 호환성이 깨지는 변경은 **Breaking:**을 붙여 맨 앞에 쓴다.

-

## 확인 사항

> 이번 실행에서 실제로 확인한 것만 체크한다. 확인하지 않은 항목은 비워 둔다.

- [ ] 바뀐 동작에 대한 테스트를 추가·수정했다
- [ ] 로컬에서 테스트 통과 (`<테스트 명령어>`)
- [ ] 린트·타입 검사 통과 (`<린트/타입체크 명령어>`)
- [ ] 동작이나 설정이 바뀐 곳의 문서를 갱신했다
- [ ] 비밀 정보, 인증 정보, 로컬 설정이 커밋에 들어가지 않았다

## 리뷰 포인트

> 특히 봐 줬으면 하는 부분, 검토한 대안, 알려진 한계. 없으면 지운다.

## 관련 이슈

> `Closes #123` / `Refs #456`. 없으면 지운다.
